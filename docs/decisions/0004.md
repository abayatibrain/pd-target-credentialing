# ADR-0004: Batch integration
Date: 2026-05-18
Status: Accepted (Armin 2026-05-18)

## Context

Smajić 2022 contains around eleven donors processed across multiple
batches. Donor identity, batch, and disease status are partially
confounded — a pattern that is generic in single-nucleus disease cohorts
because samples are processed in waves and PD vs control distinction
is not blinded at the bench. Without integration, downstream clustering
will group nuclei first by donor or by batch and only secondarily by cell
type. Without integration, cell-type-anchored DE is impossible because
the cell types themselves cannot be identified consistently across donors.

The integration method must (a) align nuclei of the same biological cell
type across donors and batches and (b) **preserve** disease-relevant
expression differences within cell types. A method that over-integrates
will erase the very signal we are trying to measure.

## Options considered

### A. Harmony
Iterative soft k-means correction in PCA space. Fast on CPU. Deterministic
given a seed. Widely cited and benchmarked. Operates in a fixed-dimensional
embedding space.
- Pros: scale-appropriate for ~10 donors; fast; deterministic; documented
  failure modes; well-tested for snRNA-seq.
- Cons: corrects in PCA space, so does not produce normalized expression
  values directly; over-correction risk is real and must be checked by
  comparing pre- and post-integration UMAPs (a check ADR-0001 already
  commits the README to showing).

### B. BBKNN (batch-balanced k-NN)
Modifies the neighborhood graph to balance batches in each neighborhood.
- Pros: very fast; minimal model assumptions.
- Cons: only affects the graph, not the embedding. Downstream methods
  that need an integrated low-dimensional representation (e.g., marker
  scoring across donors) have no good handle. Less informative for the
  exploratory plots that the README will rely on.

### C. scVI
Variational autoencoder that models batch as a covariate. Returns a
latent embedding and corrected normalized expression.
- Pros: most flexible; explicit probabilistic model; can scale to millions
  of cells; produces a denoised expression matrix.
- Cons: stochastic (training-run-to-training-run variation); GPU is needed
  for reasonable training time; the model is heavier than the data warrants
  at the Smajić scale; reproducibility requires pinning torch versions,
  random seeds, and CUDA build versions in CI — substantially more
  reproducibility surface area than the alternatives.

## Criteria for choosing

1. **Scale-appropriate.** Smajić has ~41k nuclei and ~11 donors. A method
   designed for millions of cells across hundreds of batches is over-equipped
   here, and the extra complexity buys nothing.
2. **Deterministic reproducibility.** The repo's `v1.0.0` acceptance
   criterion (§4.6) requires the demo notebook to be reproducible. Any
   stochastic training step expands the "things that can drift" surface.
3. **CPU-runnable.** Demo notebook must run on a 16 GB MacBook per the
   §4.6 acceptance criterion. GPU dependency disqualifies methods that
   require one.
4. **Documented failure modes.** Over-integration is a known integration
   pitfall. The chosen method must have a published characterization of
   when it over-corrects.

## Decision

**Option A: Harmony.**

Configuration:
- Integrate over the donor variable; not over disease status (integrating
  disease away is the failure mode we are avoiding).
- Theta (entropy regularization) at the default; sigma at the default.
  Departures from defaults require a follow-up ADR.
- Apply Harmony to the first 30 PCs (computed on the log1p layer per
  ADR-0003). Cell-type annotation operates on the harmony-corrected
  embedding (ADR-0005); pseudobulk DE operates on raw counts and never
  uses the integrated embedding (ADR-0006).

## Consequences

- The README must show pre- and post-integration UMAPs side by side so a
  reader can see that integration did its job without over-correcting.
- Donor and batch effects on cell-type composition (e.g., PD samples
  having fewer DA neurons) must be analyzed at the *composition* level
  after integration; integration does not solve cell-type-composition
  shifts.
- Switching to scVI later would force ADR-0005 to be re-validated against
  the new embedding. The cost is real but bounded.

## Open questions for Armin

1. Confirm Harmony, or override to scVI / BBKNN with the cost above
   acknowledged.
2. Confirm that integration is over donor and *not* over disease status.
