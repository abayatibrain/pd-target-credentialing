# ADR-0012: Reactome ContentService client design
Date: 2026-05-18
Status: Accepted (§1.3 — Cowork-decides engineering choice)

## Context

Reactome supplies authoritative pathway definitions (e.g., R-HSA-5205685
broad mitophagy; R-HSA-5205647 PINK1/Parkin specifically). These define
which genes belong to a pathway for the purpose of pathway-enrichment
analysis and pathway-aware scoring later in the pipeline.

The design constraints are the same as the OpenTargets client (ADR-0011):
reproducibility requires version pinning + caching; reliability requires
retries. Reusing the shared `_http/` helpers is the right move.

## Decision

- Reuse `_http/cache.py` and `_http/retry.py` (designed in ADR-0011's
  consequences).
- Endpoint: `https://reactome.org/ContentService/`. Sync httpx.
- API surface (Python-side):
  - `ReactomeClient.get_pathway(pathway_id: str) -> Pathway`
  - `ReactomeClient.get_pathway_participants(pathway_id: str) -> list[str]`
    — returns approved HGNC symbols by resolving every Reactome-returned
    symbol through the HGNCResolver (ADR-0010).
  - `ReactomeClient.get_version() -> str`
- Version is captured at client construction (Reactome publishes a
  release number); cache keys include it so a release bump invalidates
  cached responses.
- The well-known PD-relevant pathway IDs (R-HSA-5205685, R-HSA-5205647)
  are documented in the module docstring as a convenience, but the
  client itself takes any pathway ID.

## Consequences

- Reactome and OpenTargets share retry/cache plumbing; failure modes are
  symmetric.
- Pathway-participant lists are HGNC-clean by construction. Any Reactome
  symbol that fails to resolve gets logged at WARNING and excluded.
