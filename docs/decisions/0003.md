# ADR-0003: Normalization
Date: 2026-05-18
Status: Accepted (Armin 2026-05-18)

## Context

After per-nucleus QC (ADR-0002), counts must be normalized before any
distance-based step (PCA, neighborhood graphs, clustering). The normalization
choice influences cluster shape, marker discoverability, and how
visualization figures look — but, critically for this repo, has *limited*
influence on the primary statistical result because the headline DE
analysis runs on raw counts at the pseudobulk level (ADR-0006). The
normalization in this ADR is therefore a within-cell normalization for
exploratory and annotation steps only, not for primary DE.

## Options considered

### A. log1p with library-size scaling
Scale counts to a common total per nucleus (e.g., 10⁴), then take log(x+1).
This is the scanpy default and the most common snRNA-seq normalization.

### B. scran (deconvolution-based size factors)
Pool nuclei into groups, deconvolve pooled size factors, apply them. Designed
for low-count single-cell data; reduces noise in low-coverage cells.

### C. SCT (Pearson residuals via NB regression)
Per-gene negative-binomial regression on sequencing depth, returning Pearson
residuals as the "normalized" output. Default in Seurat; well-studied;
produces a fundamentally different output space (real-valued residuals
rather than log-counts).

## Criteria for choosing

1. **Compatibility with downstream pseudobulk DE.** The headline DE step
   (ADR-0006) operates on raw counts at the donor × cell-type level. The
   within-cell normalization in this ADR therefore only needs to be good
   enough for clustering, integration, and marker scoring — not perfect.
2. **Reproducibility.** Deterministic output for a given input is preferred.
3. **Ease of explanation.** A README reader without single-cell expertise
   should be able to follow the choice.
4. **Tooling maturity in scanpy.** The whole pipeline is scanpy-native;
   forcing the user through Seurat for normalization fragments the stack.

## Decision

**Option A: log1p with library-size scaling to 10⁴.** Applied to the
QC-filtered count matrix to produce the `.X` field used for PCA and
neighborhood graph construction. Raw counts are preserved separately in
`.layers["counts"]` and are the input to ADR-0006's pseudobulk DE.

## Consequences

- Marker-based annotation (ADR-0005) uses the log1p layer.
- Integration (ADR-0004) operates on PCs computed from the log1p layer.
- DE (ADR-0006) does **not** use the log1p layer; it pseudobulks the
  preserved raw counts.
- Switching to SCT or scran later requires re-running ADR-0004 (different
  PC space) and ADR-0005 (different marker score distributions). The cost
  of changing is not trivial; a superseding ADR is required if so.

## Open questions for Armin

1. Confirm log1p, or override to scran or SCT (and accept the cost above).
2. Confirm the scaling target of 10⁴ counts per nucleus, or specify another.
