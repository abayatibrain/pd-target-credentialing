# ADR-0010: HGNC alias-resolver design
Date: 2026-05-18
Status: Accepted (§1.3 — Cowork-decides engineering choice; not biology)

## Context

§3.4 of the Cowork brief commits this repo to a single source of truth
for gene symbols: HGNC, approved symbol only, no aliases silently
accepted. Every downstream module — IO loaders, DE, OpenTargets queries,
Reactome lookups — depends on a working resolver. The resolver is
load-bearing infrastructure.

Three design choices need to be locked in before code is written:
1. The cache format and schema.
2. The policy when one input symbol resolves to multiple approved
   symbols (legitimately happens — some legacy aliases were ambiguous).
3. The logging level and surface for every alias substitution event.

## Options considered

### Cache format
- **A1: Parquet on disk.** Columnar, easy to query, integrates with the
  rest of the pipeline (which is pandas/pyarrow-native).
- **A2: SQLite.** Better for many-tiny-writes; supports concurrent reads.
- **A3: JSON files keyed by symbol.** Simplest; no extra dependency.

### Multi-mapping policy
- **B1: Silently choose the first approved symbol.** Bad — masks real
  biological ambiguity.
- **B2: Raise an exception.** Strict; halts the pipeline on a debatable
  case.
- **B3: Return `MultiMappingError` as a value, log ERROR, write the
  case to `data/hgnc_multimappings.csv` for human review.** Doesn't
  halt; surfaces the problem.

### Logging
- **C1: DEBUG on every resolution.** Noisy.
- **C2: INFO on every resolution.** Still noisy.
- **C3: WARNING on every alias substitution, INFO on direct approved
  matches, ERROR on multi-mappings or not-found.** Volume-appropriate.

## Decision

- **A1: Parquet on disk** at `$XDG_CACHE_HOME/pd_target_credentialing/hgnc_aliases.parquet`.
  Schema: `input_symbol, approved_symbol, hgnc_id, ensembl_id, entrez_id,
  match_type, resolved_at, hgnc_release`. Read on resolver construction;
  appended-and-rewritten on cache miss.
- **B3: `MultiMappingError` value type + logged + CSV surfaced.** The
  CSV path is configurable; default is `data/hgnc_multimappings.csv`
  (gitignored by default; the user can opt in to committing it for
  audit purposes).
- **C3: WARNING on alias substitution.** Per §3.4 verbatim.

## Consequences

- Pyarrow is a hard dependency (already in `pyproject.toml` foundational
  deps).
- Tests must mock the HGNC API entirely via `respx` (no live network in
  CI).
- A first-run resolution of N symbols issues N API calls; subsequent
  runs are zero-network. This is the right trade-off.
- The cache file is **never committed** (per §2.6 data-handling rules);
  it lives under the user's cache dir.
